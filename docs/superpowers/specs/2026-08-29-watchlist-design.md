# 追剧记录设计

## 目标

在“我的”页提供独立的“追剧记录”入口，用于本地保存剧名、用户维护的分类和当前集数。用户可以直接输入集数，也可以通过减一和加一快速更新。

## 范围

- 默认分类：电视剧、电影、动漫、短剧。
- 用户可新增、改名、调整排序和删除分类。
- 用户可新增、编辑、删除和长按排序追剧记录。
- 每条记录只保存当前集数；不增加总集数、播放链接或在线同步。
- 现有数据备份会包含追剧分类与记录，同时继续导入旧版倒计时备份。

## 导航与界面

### 入口

“我的”页新增“追剧记录”列表入口，展示分类数量和记录数量。该页面使用顶部返回按钮，系统返回时回到“我的”。不增加第四个底部导航项目。

### 追剧列表

- 顶部显示“追剧记录”、记录数和分类管理入口。
- 分类以横向筛选项显示，默认有“全部”。
- 卡片显示剧名、分类和“第 N 集”。
- 卡片内的减一、加一立即保存；当前集数为 0 时禁用减一。
- 点击卡片进入编辑；更多菜单提供删除；长按卡片排序。
- 空列表提供“添加追剧记录”主操作。

### 添加与编辑

- 必填：剧名、分类、当前集数。
- 当前集数接受非负整数输入，也可通过减一、加一调整。
- 保存前阻止空剧名和无分类的记录。

### 分类管理

- 分类名称必填且同名不允许保存。
- 分类可以新增、改名和长按排序。
- 删除空分类直接完成；删除含记录的分类时，必须选择目标分类转移记录。
- 最后一个分类不可删除，确保新增记录始终有可选分类。

## 数据与迁移

数据库由版本 9 升至 10，保留现有 `countdown_records` 不变，并新增：

- `watch_categories`：`id`、`name`、`sortOrder`。
- `watch_records`：`id`、`title`、`categoryId`、`currentEpisode`、`sortOrder`。

9 到 10 的迁移会创建两张表并插入四个默认分类。新表使用外键关联分类；删除或转移分类与记录的操作由 Repository 事务完成。

## 备份兼容

备份 JSON 扩展为倒计时记录、追剧分类和追剧记录三个部分。读取旧备份时，缺少追剧字段视为没有追剧数据；导入新备份时保留既有记录，并重新映射分类 ID，避免与本机 ID 冲突。

## 错误与边界

- 集数最小为 0，输入无效值不保存。
- 分类删除时没有可转移的目标分类，显示不能删除的提示。
- 更新、备份、恢复与应用升级不会清除追剧数据。

## 验证

1. Room 9 到 10 迁移后原倒计时记录仍可读取，且默认分类存在。
2. 分类新增、改名、转移删除与最后一个分类保护可验证。
3. 记录增加、减少、直接输入、分类筛选和排序可验证。
4. 新旧备份均可导入，追剧数据在导出后可恢复。
5. 运行 Kotlin 编译与调试包构建。
